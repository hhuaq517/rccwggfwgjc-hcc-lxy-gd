# 字体版权比对（宣传物料）

输入宣传物料（**用户给几张就审几张，默认一张**；有源文件最好，只有成图也行）＋公司的《已购字体清单》，
输出四档结论：**✅ 在清单内且在授权范围 / ⚠️ 已购但需核授权书 / ⛔ 已知排除（禁用）/ 🚫 当前清单中未见**。

**⛔ 与 🚫 必须分清**：⛔ 是**有据可查的禁用项**（改名冒用、来源存疑），**立即替换**；
🚫 只是**当前清单里查不到** —— 如实列为风险项并给出替换建议即可。

**⚠️ 不要向用户追问"这款字体在不在公司授权包里"（物料所属公司 2026-09-19 指定）。**
**《已购字体清单》就是唯一口径**：清单里没有 = 🚫，直接给替代方案，交付照常走完。
用户会**主动**告知新增的已购字体，届时补录清单、重跑比对即可刷新结论。
（历史背景：站酷酷黑、方正兰亭大黑两次都是清单漏登 —— 所以**措辞留余地**，
但余地只体现在报告用词上（"当前清单中未见此款"），**不要变成向用户提问、更不要因此阻塞交付**。）

## 审查范围（硬约束，优先级高于下文一切流程）

**只审用户在当前消息里点名/发送的那一个文件。发一个就审一个，不要扩大。**

- ❌ **禁止为了"了解上下文"去列目录**（`ls` / `glob` / `dir` / 遍历父文件夹）
- ❌ **禁止把同目录、同文件夹、名称相近的其它图一并审查** —— 哪怕是同一场活动的其它尺寸、
  `xxx-v1.png` 与 `xxx-v2.png` 这种看着像一套的，也不许自动带上
- ❌ **禁止给多个文件传参**：`extract_fonts.py` 虽然接受多个路径，那也是**用户明确点名的那几个**，
  不是"顺手把目录里其它文件都列上"
- ✅ 交付物只对应这一个文件：一份报告 + 一份字形记录，文件名与被审文件一一对应
- ✅ 需要素材时**只读用户给的那一个路径**，不推断、不扩展

**唯一例外**：用户在**当前消息**里明确说了范围，例如"这个文件夹里的图都看一下""这几张一起审"。
此时也要**先把将要审的文件清单列出来给用户确认**，再执行；审完按文件分别出结论，不要混成一份。

**为什么写死这条**：用户丢一张图过来，要的是**这一张**用的什么字体。
把同目录别的图一并审，会产出用户没要的交付物、把结论与文件名对错号，
还会让用户以为"我只发了一张，怎么审了八张"。

## 第 0 步（强制）：先确认要走字体线，再动手

用户**只把文件丢过来、没有说要审什么**时，**不要默认开跑字体比对** ——
先用 `AskUserQuestion` 问清 `审查类型`（三个选项）：**广告法合规审核 / 版权字体审查 / 两者都要**。

> ⚠️ 这里问的是**审查类型**（审哪条风险线），**不是文件范围**。
> 文件范围默认就是"用户发来的那一个"（见上节），不需要问、也不允许自行扩大。

- 用户选了含字体线的选项 → 按本技能往下走。
- 用户只选「广告法合规审核」→ 转 `ad-compliance-check`，字体线不跑。
- **用户已明确说"看字体""字体有没有问题"→ 跳过询问，直接执行。**
- 只有成图、没有源文件时，**问的时候就要讲明**：本次只能做字形比对，
  给的是**排除性结论**（能排除多数未购字体，不能反证"就是某款字"）；有 PSD/AI/PDF/PPTX 才能给确证结论。

## ⚠️ 能力边界（必读，不要越界承诺）

**不要把"看着像某字体"当作版权结论。** 中文字库侵权认定靠字形重合度鉴定，不靠肉眼。
本技能的做法是：**确定性来源（元数据）优先，量化打分（字形比对）次之，两者都拿不到时才提兜底方案。**

- 能做到：读源文件里写死的字体名（100% 准确）；字形相似度打分（可验证的相对排名）。
- 做不到：仅凭成图给出"就是 XX 字体"的结论。相似度只能缩小范围。
- 最终授权结论**永远以字体权利方出具的授权书为准**。报告里必须保留这句话。

## 三层流程

| 层 | 方法 | 可靠性 | 成本 | 前提 |
|---|---|---|---|---|
| 1 | 源文件元数据提取 | 确定性 | 免费 | 有 PSD/AI/PDF/PPTX/DOCX/XLSX |
| 2 | 字形比对打分 | 量化排名 | 免费 | **本机已装已购字体**（换电脑先跑 `check_fonts.py`）+ 成图 + 知道图上文字 |
| 3 | 付费识别接口 | 候选 + 置信度 | ¥0.5/次 | 前两层都不行时的兜底 |

**按顺序用，不要跳层。** 有源文件就不必做字形比对；两层都有就交叉印证。

⚠️ **只有第 2 层依赖本机字体文件**。第 1 层读的是文件里写死的字体名、第 3 段是纯字符串匹配，
两者换任何电脑都一样跑 —— 详见下节「换电脑 / 打包分发」。

## 脚本用法

七个脚本互相解耦，可单独跑，也可串起来。

先明确一件事：**清单里的 aliases 必须从字体文件里读出来，不能靠记忆猜。** 猜错的后果是合规字体被误判成「不在清单内」。

### 0. 读字体文件的真实名称（填清单用）

```bash
python scripts/font_info.py <字体文件或目录> [--json fonts.json] [--all-names]
```

- 读 name 表：family / subfamily / full_name / postscript；`--all-names` 再加 copyright、trademark、manufacturer、designer、version
- **同一款字体在 name 表里有多条记录**（Mac / Windows、英文 / 简中各一份）。很多中文字体的英文记录是乱码，正确名称在简中记录里 —— 脚本按「语言优先级 + 解码质量」打分选，不取第一条
- `--all-names` 还能用来**查来源**（见下方「坑二」）
- 典型用法：`--filter` 只看含某关键词的字体

### 0.5 字体体检（**换电脑后的第一步**）

```bash
python scripts/check_fonts.py assets/licensed-fonts.json [--font-dir DIR]
```

在开始任何比对之前先跑它，确认本机装了清单里的哪些字体、还缺哪些。

- 输出：扫描了哪些目录 / 已购字体命中几款 / 覆盖率 / **缺哪几款（含文件名与厂商）/ 该装到哪**
- 退出码：`0` = 覆盖率达标（第二层可用）；`1` = 覆盖率不足；`2` = 清单读不了
- 顺带检查 `_excluded` 里的禁用字体**是否还装在本机**（排除 ≠ 卸载，提醒别误用）
- 默认门槛 60%（`--min-coverage` 可调）。不定 100% 是因为个别字体可能只在设计机上装过，
  缺一两款不影响排名可信度；**缺掉大半时结论会完全失真**，必须拦住

### 0.6 字体文件是怎么定位的（不用管路径，但要懂原理）

```bash
python scripts/font_lookup.py [额外目录...]
```

`assets/licensed-fonts.json` 里的 `font_file` **只写文件名**（如 `FZLTHJW.TTF`），
运行时会自动在这些目录里按文件名查找，**装在哪个目录都能找到**：

- Windows：`%WINDIR%\Fonts`、`%LOCALAPPDATA%\Microsoft\Windows\Fonts`
- macOS / Linux：`/Library/Fonts`、`/usr/share/fonts`、`~/.fonts` 等
- 追加：`--font-dir`（可重复）或环境变量 `FONT_LICENSE_AUDIT_FONT_DIRS`
  （多个目录用系统路径分隔符隔开，Windows 用 `;`）

**不要再往清单里写 `C:\Users\某人\AppData\...` 这种绝对路径** —— 换台电脑就全指向空。
旧版写成绝对路径也能跑（文件真在就直接用），但那是靠运气，不是设计。

### 1. 提取字体名（第一层）

> ⚠️ **这里的「文件1 文件2」只能是用户在本次消息里点名的那几个**，不是"把目录里其它素材都列上"。
> 传目录不会生效（脚本会明确拒绝并提示），但**更不要先去列目录**——见文首「审查范围」。

```bash
python scripts/extract_fonts.py <文件1> [文件2 ...] --json extracted.json [--psd-layers]
```

- 按**文件魔数**判定格式，不看扩展名
- 支持：docx / pptx / xlsx（`w:rFonts`、`a:latin`、`a:ea`、`xl <name val>`）、
  pdf 与 PDF 兼容的 ai（`/BaseFont`、`/FontName`，自动剥掉 `ABCDEF+` 子集前缀）、
  psd（解析每个 TySh 文字块的 `/Text` + `/FontSet` + `/RunArray` + `/RunLengthArray`，
  **按字符数逐段归属，只报真正分到字符的用字**，详见下节；并自动**拆解智能对象**）、
  图片（PNG tEXt / EXIF，多为空）
- `--psd-layers` 打印**逐层用字映射**（图层文字 → 字体 → 字数），排查误报时先看它
- `--no-smart-objects` 关掉智能对象拆解（内嵌素材很大、只想快跑时用）
- 只有成图时会输出 `no-font-metadata`，此时转第二层

### 1.5 PSD 专项（三个坑，都踩过）

PSD 是**信息量最大**的一层：它记着图层实际用了哪款字，结论是**确证性**的，比字形比对强得多。
但解析有三个必踩的坑，任何一个没处理，结果都是错的 —— 而且**不报错，静默给出空或错的答案**。

**坑一：PSD 描述符字符串是 UTF-16BE。** 字体名以 `\xfe\xff` BOM 开头，后面是 UTF-16BE。
按 latin-1 解出来全是 `\x00F\x00Z...` 夹空字节的串，被字符过滤一过就全丢 —— 表现为
**"未提取到任何字体名"**。这时很容易误判成"这批素材只有成图"，白白退到第二层去猜。
✅ 判据：`raw.startswith(b'\xfe\xff')` → `raw[2:].decode('utf-16-be')`；否则才用 latin-1。

**坑二：字符串不能用正则贪婪匹配。** PSD 字符串里 `\` 和 `)` 都会被反斜杠转义，
`/Text\s*\((.*?)\)` 之类会**把后面整个块吞进字符串**（实测把 engine data 全吃进去了，
读出来的"文字"是一堆乱码）。✅ 必须逐字节扫描，遇**未转义**的 `)` 才结束。

**坑三：`/Font` 有两个来源，其中一个不是用字。** PSD 里的 `/Font N` 出现在两处：
- `/RunArray > /StyleSheet > /StyleSheetData > /Font N` —— **这才是图层实际用字**，N 是 FontSet 下标
- `/StyleSheetSet > /Name (正常 RGB) > ... > /Font N` —— 这是**文档默认文本样式**，与图层无关

实测这一次：10 个文字层的 RunArray **全部指向 Font 0**（= 方正兰亭黑 / 兰亭大黑），
而 `(正常 RGB)` 默认样式固定指向 **`AdobeHeitiStd-Regular`**。
不区分的话，就会把 **Adobe 黑体 Std**（随 Adobe 软件附带的商业字体，绝大多数公司都没买）
当成"图层实际用字"报成一处 🚫 侵权风险 —— **纯属误伤，会让设计白改一轮字**。
✅ 做法：先 `blk.find(b'/StyleSheetSet')` 切断，只在切点之前找 `/Font N`。
**这条比前两条更危险：前两条是漏报，这条是误报。**

**另外要过滤的噪声名**（这些不是字体，是 Photoshop 的占位/设置项）：
`PhotoshopKinsokuHard` / `PhotoshopKinsokuSoft`（日文禁则换行规则集）、`AdobeInvisFont`（隐形占位字体）、
`正常 RGB`（文档默认样式名）。

**坑四：`/FontSet` 里出现 ≠ 该图层用了它（0 字符的僵尸 run）。**
一个图层的 `/FontSet` 常常列着 3–5 个字体名（历史编辑留下的），而真正用字要看
`/StyleRun` 里的两份数组：
- `/RunArray` —— 按 run 顺序给出**字体下标**（下标指向本层的 `/FontSet`）
- `/RunLengthArray` —— 按同样顺序给出**每个 run 的字符数**

两份数组**按下标一一对应**，必须**按位对齐**后才能算出「每款字体各画了多少字」。
只把 `/FontSet` 列出来，或只收集 run 里出现过的下标（不管长度），都会把没用的字体报成 🚫 ——
**和坑三一样是误报，而且更隐蔽**，会让设计白改一轮字。

✅ 判据：**各 run 的字符数累加，应等于 `/Text` 的字符数**（含行尾 `\r`，实测总是 +1）。
对不上的 run（长度为 0，或整份数组对不齐）**不计入用字**；对不齐时降级为
「按整份 FontSet 报」并在备注里标明**不确定**。

> **2026-09-20 修正（原先这条写的判据是错的）**：早期版本说"三条橙条的韵动特黑 run 长度为 0"，
> 但用 `psd_tools` 逐层对拍后发现 —— **这一份 PSD 里根本没有 0 长度的 run**。
> 真实情况是：**字体下标 0（= 韵动特黑）的那些 run 确实分到了字符，只是很短，装的是「数字」。**
> 逐段归属后（`--psd-layers` 输出，40 层逐层核过）：
>
> | 图层文字 | 兰亭粗黑 | 韵动特黑 |
> |---|---|---|
> | 全款大额优惠叠加,每人仅限1个名额！ | 18 字 | 1 字（数字 `1`） |
> | 万元以上全款或尾款送价值399中公学豆耳机! | 20 字 | 3 字（`399`） |
> | 全款免费试学3天,不满意15个工作日全退! | 19 字 | 3 字（`3`、`15` 两个 run） |
>
> 成因很常见：**文字是先用韵动特黑打的，改字时才把中文切到兰亭粗黑，数字/标点留在原字体上**
> —— Photoshop 的 run 边界正好切在「中英混排」处，所以数字会单独成段、指向另一款字体。
> **这类"数字用了另一款字"必须报出来**（它同样是实际用字，也照样有版权风险），
> 但**不能**把整层都说成未授权字体。
>
> **总结论不受影响**：这份 PSD 仍是 ✅3 / 🚫1（韵动特黑本来就从「20」那层被报出），
> 与修正前一致。

**坑五：PSD 字符串的转义是「按字节」的，UTF-16BE 汉字中间也会出现 `0x5C` / `0x29`。**
实测：`天` = U+5929 在文件里写作 `59 5C 29`（`0x29` 被转义），`尾` = U+5C3E 写作 `5C 5C 3E`。
所以逐字节扫描时必须**遇到 `0x5C` 就吞掉其后一个字节**：
- 不吞 → 多出一个字节，**后面整段错位**（解出来是 `屜㹫㺐Ŏ` 这类乱码，但程序不报错）；
- 把被转义的 `0x29` 当成字符串结束 → **文字被腰斩**（"万元以上全款或" 后面的全丢）。
✅ 已验证：`/Text` 取出的文字与 `psd_tools` 的 `engine_dict['Editor']['Text']` 逐字一致。

**坑六：字体名不一定带 BOM，也不一定是 UTF-16。**
`\xfe\xff` 开头 → UTF-16BE；纯 ASCII → ascii；**含成对 NUL** → 漏写 BOM 的 UTF-16BE；
其余**先试 GBK**、再 utf-8，最后才 latin-1。
⚠️ 别用 latin-1 兜底中文名 —— 旧格式（中文 Windows 存的）就是 GBK，
用 latin-1 解出来是一串**能通过长度检查的乱码**，比报错更难发现。

**另外要过滤的噪声名**（这些不是字体，是 Photoshop 的占位/设置项）：
`PhotoshopKinsokuHard` / `PhotoshopKinsokuSoft`（日文禁则换行规则集）、`AdobeInvisFont`（隐形占位字体）、
`正常 RGB`（文档默认样式名）。
「声明过但一个字都没分到」的字体（如 `SimSun`、`AdobeHeitiStd-Regular`）会写进**提取备注**：
它们**不参与比对**，但列出来便于人工复核 —— 报告里"没提某款字"和"查过确实没用"是两回事。

**逐层映射（想知道"哪一段文字用了哪款字"就这么做）**：
按 TySh 块解析，每块同时取出 `/Text`（判身份）与 `/FontSet` + `/RunArray` + `/RunLengthArray`（判用字），
两者配对即得「图层 → 字体 → 字数」映射 —— **已内置**，加 `--psd-layers` 直接打印：

```bash
python scripts/extract_fonts.py <文件.psd> --psd-layers
# · 万元以上全款或尾款送价值399中公学豆耳机! /   → FZYDTHJW--GB1-0 3字 / FZLTCHJW--GB1-0 20字
```

**怎么自证（不必凭感觉）**：用 `psd_tools` 对拍同一份文件，两边必须逐层一致 ——

```python
# layer.engine_dict['Editor']['Text']                ← 该层文字
# layer.engine_dict['StyleRun']['RunArray'][i]['StyleSheet']['StyleSheetData']['Font']  ← 第 i 段字体下标
# layer.engine_dict['StyleRun']['RunLengthArray'][i] ← 第 i 段字数
```

实测对拍：7月23日那份 **10 层**、7.30 那份 **40 层**，脚本输出与 `psd_tools` **逐层零差异**。

导出合成图：`PSDImage.open(p).composite()` → PIL Image，既可用于报告插图，也可直接喂给
`ad-compliance-check` 的 `annotate.py` 画标注框（框位可直接用 `layer.bbox` ÷ 画布尺寸，比目测准得多）。

### 1.6 智能对象拆解（把盲区变成结论）

**智能对象（logo / 素材图 / 内嵌设计稿）是独立文件，内嵌在 PSD 里**，光学外层 PSD 一个字都读不到。
`extract_fonts.py` **默认会自动把它们拆出来逐个解析**（依据 `psd_tools`，按内容去重、单个上限 64 MB、最多 16 个）。

- 实测一份 40 层的推图里内嵌 **6 个**智能对象：`矢量智能对象.ai`（其实是 PDF）、
  `图层 17.psb` / `图层 7.psb`（内嵌 PSB）、若干个 PNG。
  拆出来后：**内嵌 PSB 里没有 `TySh`、AI/PDF 里没有 `/BaseFont`、PNG 没有字体元数据**
  → 说明这些素材**文字已转曲 / 本就是位图**，此路不通。
- **能把"读不到"升级成"查过，里面确实没有字体信息"** —— 报告里这两种写法含义完全不同：
  前者是盲区，后者是可以签字确认的结论。
- 若内嵌的是**带文字层**的 PSB，字体名会照常被读出，标签写作 `psd:智能对象(<原文件名>)`。
- 没装 `psd_tools` 时**自动跳过并记一条备注**，其余功能不受影响（`pip install psd-tools` 后可重跑）。
- 落盘时**不用内嵌原名**：内嵌文件名可能是中文 / 含空格 / 含路径分隔符，
  统一写成 `so01.psb` 这类安全名，避免在别的机器上因编码问题出意外。

**⚠️ 图层存在 ≠ 图层出图（影响"用了多少字"的口径）**：PSD 里常有 `visible == 0` 的隐藏层，
和被上层色块完全盖住的层 —— 它们在合成图里不显示，但照样能被解析出字体名。
报"用量/位置"时应以**实际出图的层**为准，并把隐藏/被遮挡的层在报告里单列一句
（实测：「教师招聘产品」卡内一层「奖金班免费升级为12天集训班」被上一行色块盖住、整层不出图，
它的字体是兰亭黑，**不影响结论**，但"奖金班"这条实际只有 2 处可见，不是 3 处）。
被遮挡层也会给广告法那边造成"幽灵框"，`ad-compliance-check` 的 PSD 节已写明核对办法。

**PSD 也读不到的东西（盲区，必须写进报告）**：
- 做了**描边 / 渐变 / 立体特效后栅格化**的标题 —— 已经不是文字层，PSD 里没有字体记录。
  偏偏它常常是全图最大的那行字（最容易被字体厂商取证盯上）。
- **智能对象**：先按上节**把它拆开再下结论**；拆完内部也没有字体信息，才列入盲区。
- 这些类要在报告里单列「本次未能覆盖」，**不能默认它们没问题**。
- 顺带：找栅格化标题的位置时别用"灰度 < 200"——**深色底整块的灰度可能就小于 200**，
  会把背景全判成墨迹。改按颜色取掩码（白字 `R>200&G>200&B>200`、黄字 `R>190&G>140&B<140`）。

### 2. 字形比对（第二层）

**成图比对有三条硬要求，漏掉任何一条结论都会失真（都是实测踩出来的）：**

1. **必须先二值化。** 图上文字通常是彩色的（红字 / 黄字 / 白字），而候选字体渲染出来是纯黑。直接比对时灰度差被"颜色不同"系统性拉大 —— 实测把所有候选压在 45~64 分、前两名只差 1~5 分，**区分度被完全吃掉**。先二值化把颜色差异归零，再比，比的就真是字形。
2. **必须加"未购对照字体"。** 只拿已购字体当候选，等于让已购选手在自家赛道上跑 —— 万一图上用的是没买的字体，它也会在已购里"矮子里拔将军"给出看似合理的答案。要把没买的通用字体（黑体 / 微软雅黑 / 雅黑粗体 / 等线 / 宋体）一起放进候选，才可能发现真相。
3. **必须看跨样张统计，不能只看单样张第一名。** 实测有一处样张把「站酷快乐体」推上第一，可它其余三处排名是 13 / 11 / 15 —— 典型的孤立误匹配（那处字号最小，细节丢失最多）。判读要看**平均分**与**排名稳定性**。
4. **必须先剔除"失效样张"，再下结论。** 判据：**某样张的最佳分数远低于其他样张，且 34 款候选被整体压低**（实测：某样张最高仅 51.2，其余样张 73.8~80.8）。成因是**文字被横向压缩、或字距（tracking）被调过** —— 破坏了比对所依赖的宽高比，所有候选一起失分。辅助信号：top 候选的 `宽比` 普遍偏离 1.0（实测 0.83~0.96）。
   **这时不能写"图上用了别的字体"，只能写"无法判定"**，并补一处新样张替换（换行、换正文段落通常就能拿到合格样张）。据此下结论会得出完全错的排名。

**样张选取的实操经验**：带**立体描边 / 发光 / 渐变 / 弧形横幅斜排**的文字一律不能用；正文小字比标题大字好用；同一处的文字若含 `/`、`+`、`=` 等符号不影响比对。

先 `Read` 图片看清文字，写一份 spec（**候选池交给清单自动生成，不用手工填字体路径**）：

```json
{
  "image": "C:/path/poster.png",
  "target_h": 64,
  "samples": [
    {"label": "主标题", "text": "全年无限学", "box": [0.05, 0.18, 0.62, 0.28]},
    {"label": "副标题", "text": "教师招聘专项", "box": [0.05, 0.30, 0.55, 0.36]}
  ],
  "top": 5
}
```

需要临时补一两款不在清单里的字体时才写 `candidates`，
path 只写**文件名**即可，并可标 `"group": "control"` 归入对照组：

```json
"candidates": [{"label": "汉仪旗黑", "path": "HYQiHei.ttf", "group": "control"}]
```

**成图走两步；有源文件直接走第一层，不必做这个。**

```bash
# 第一步：提取干净的二值样张（成图必做）
python scripts/extract_samples.py spec.json --out-dir work/

# 第二步：比对（--manifest 会按《已购字体清单》自动生成已购候选，并自动补未购对照）
python scripts/glyph_match.py work/spec_bw.json \
       --manifest assets/licensed-fonts.json --out glyph.json
```

**候选池会自检，缺字体直接拒跑（退出码 3）。** 这是本技能最重要的一道防线：

- 第二层的原理是「把候选字体渲染成像素再比」，**缺字体不会报错**，但排名会变成矮子里拔将军。
  实测过：只缺已购、系统字体还在时，脚本照常输出一份排名，把未购对照的微软雅黑推到第 1 名。
- 所以已购字体解析率低于门槛（默认 60%）时**拒绝输出排名**，改为打印缺了哪几款、怎么补。
- 确实要看（例如只想缩小范围）：加 `--allow-partial`，结果**不可用于定款**。
- 阈值可调：`--min-coverage 0.8`。

`extract_samples.py` 做两件关键事：
- **4x 超采样后再二值化** —— 原图字号常只有 40~100px，直接二值化边缘锯齿重、字形失真；先放大再取阈值，边缘更平滑
- **极性自动判断** —— 白底红字与红底白字都能处理

⚠️ **box 必须严格落在同一种底色内。** 框进了底色不同的区域（例如红条外沿的白色卡片底），极性会判反、整张样张变成黑底白字 —— 实测踩过，出图是反的，而打分不报错，很难察觉。

⚠️ **不要做"剔除满行框线"这类像素级清理。** 粗黑体汉字的横画密集处，单行墨迹占比可以很高，会被误判成框线而**横向切碎字形**（实测把样张切成十几段）。宁可把 box 收紧来避开边框。

- `box` 用 **0–1 比例坐标**，与图片分辨率无关
- 原理：把同一串文字用每个候选字体渲染出来，与图上裁出的文字做**像素级比对**
  （墨迹 IoU + 灰度平均绝对差 + 宽度比例惩罚），输出排序与分数
- 会自动处理**深色底海报**（极性反相）与自动阈值（Otsu）
- `.ttc` 字体集用 `index` 指定第几款

**分差判读（重要）**：

| 第 1 名与第 2 名分差 | 结论 |
|---|---|
| ≥ 15 分 | 可作强线索，写进报告并注明"建议以源文件复核" |
| 5–15 分 | 只能缩小范围，需再取一处样张或走源文件 |
| < 5 分 | 无法区分，不要下结论；改用源文件或付费接口 |

同族字体（如黑体 vs 等线）分数天然接近，属于预期现象，不要据此断言。

**判读顺序：先看跨样张统计，再看单样张分差。** 单张第一名的偶然性很大，有效证据是「平均分排序 + 各样本排名」。依次看三件事：

- **平均分前几名是谁** —— 若前列全是已购、未购对照稳定落后，则"未发现未购信号"
- **有没有"单点高分、其余靠后"的字体** —— 那是误匹配，不是发现，报告中要点明
- **未购对照有没有冲到过第一** —— 这才是真信号，必须单独说明

另外，**同族已购字体覆盖充分**时（例如已购里有方正黑体 / 兰亭黑 / 兰亭粗黑 / 兰亭特黑 / 汉真广标等多款同风格黑体），即使无法定到具体某一款，风险仍然低 —— 但也**不能就此写成"已授权"**，因为若图上实际用的是同风格的**未购**字体，已购字体同样会"看着像"。这类结论要明确标注为**排除性**（没发现未购信号）而非**确证性**（证明用的是哪一款）。

### 3. 清单比对与出报告（第三段）

```bash
python scripts/audit.py --extracted extracted.json \
                        --licensed licensed-fonts.json \
                        --out 字体版权报告.md \
                        [--glyph glyph.json]
```

- **投放媒体无需询问，默认即「线上线下全平台」**（物料所属公司 2026-09-19 指定：素材线上线下全平台投放）。
  脚本 `--media` 默认值已设为该口径，**不要每次再问用户投在哪**；只有用户明确说"这批只投 XX"时才覆盖。
- 媒体判定为**双侧**：授权只写单侧（仅"网络"或仅"印刷"）**不算覆盖全平台**，会降 ⚠️ 并写明缺哪一侧。
  `全媒体 / 全平台 / 线上线下` 视为两侧通吃。
- 清单模板即 `assets/licensed-fonts.json` —— **仓内自带的是示例数据**（3 条占位条目 + 1 条排除示例），
  第一次使用前请用本单位自己的清单**整体替换 `fonts` 数组**；aliases 与 font_file 按 `font_info.py` 的实测值填。
- `font_file` 字段存本机字体文件路径，第二层字形比对可直接拿它当候选清单
- **只有「用途不覆盖」和「已过期」会降档**；`note`、「长期」这类表述只作提示，不降档
- aliases 越全越不容易漏匹配（产品名、内部 family 名、PostScript 名、简繁变体都写上）
- 匹配方式分 `exact`（归一化后完全相同）与 `fuzzy`（长度 ≥4 的子串包含，可能有假阳性）
- 多款字体同时被命中时，按「exact → 命中别名更长（更具体）→ 清单靠前」选最优，并在 fuzzy 命中时提示人工确认

## 换电脑 / 打包分发

**先划清能力边界**，别以为「拷过去就能用」：

| 环节 | 依赖本机字体？ | 换电脑后 |
|---|---|---|
| 第 1 层：源文件提取字体名（PSD/AI/PDF/PPTX/DOCX/XLSX） | **否** | ✅ 照常，结论 100% 一致 |
| 第 3 段：清单比对（`audit.py`） | **否** | ✅ 照常 |
| **第 2 层：字形比对（成图）** | **是** | ⚠️ 字体没装就**拒跑** |
| `font_info.py`（给清单补新字体时才用） | 是 | 同上 |

- **第 1 层为什么不受影响**：它读的是**文件里写死的字体名**，跟本机装没装字体毫无关系。
  所以「有源文件就能给出确证性结论」这件事在任何电脑上都成立 —— 这是本技能最可靠的一条线。
- **第 2 层为什么必须装字体**：它的做法是把候选字体**渲染成像素**再与成图比对，
  字体文件就是选手本身，缺一个少一个，没有替代方案。

### 前置条件（目标机器要有）

| 依赖 | 谁需要 | 怎么装 |
|---|---|---|
| Python 3 | 全部脚本 | 宿主一般自带托管 Python |
| **Pillow** | `glyph_match.py` / `extract_samples.py` / `extract_fonts.py`（读图片元数据用） | `pip install Pillow` |
| `psd_tools`（**可选**） | `extract_fonts.py` 拆解 PSD 里的**智能对象**（内嵌 PSB/AI，见 1.6 节） | `pip install psd-tools` |

其余脚本**只用标准库**（`os/sys/re/json/zipfile/struct/argparse/io/glob/unicodedata/tempfile`），零依赖。
**没装 `psd_tools` 也能跑**：智能对象那一步会自动跳过并记一条备注，其余结论不受影响
（只是"智能对象内部"会退化成盲区）——所以**给同事的机器上建议装上**，省得每次都要人工补一句"读不到"。
换句话说：**只走第 1 层（源文件）的话，装个 Python 就能跑，什么都不用额外装。**

### 给同事电脑的操作顺序

0. 确认有 Python 3 + `pip install Pillow`（只有要跑成图比对时才需要）
1. 拷贝技能目录（含 `assets/licensed-fonts.json`）
2. 装字体：把清单里的字体文件装进本机字体目录，**装哪个目录都行**
3. `python scripts/check_fonts.py assets/licensed-fonts.json` —— 确认覆盖率达标
4. 照常走工作流（第 2 层加 `--manifest` 即可）

字体装在非标准目录时，用 `--font-dir` 或环境变量 `FONT_LICENSE_AUDIT_FONT_DIRS`。

### 打包时注意

- **不要把字体文件塞进包里。** 已购字体的授权是给本单位的，随包分发给别的机器
  （尤其外部合作方）可能超出授权范围；且几十款字体动辄上百 MB。
  正确做法是把「装字体」写成前置步骤，让人自己装。
- **`assets/licensed-fonts.json` 是本单位的资产清单**（各款的 aliases + 授权范围 + 主体）。
  它记录的是「买了什么」，对外提供时**按需删减或替换为示例** —— 清单本身不构成授权凭证。
- 打包前删掉 `scripts/__pycache__`。

### 如果对方是外部合作方

他们不该装我们的字体，所以第 2 层在他们机器上**必然拒跑 —— 这正是想要的行为**。
对他们只走第 1 层（向对方索要源文件），或把成图拿回自己机器上比对。

## 两个最容易踩的坑（清单侧）

**坑一：产品名 ≠ 字体文件里的内部名。** PDF / PSD / PPT 里记录的往往是 PostScript 名或 family 名，和产品名差很远：

| 产品名 | 文件内部 family | PostScript 名 |
|---|---|---|
| 方正粗谭黑简体 | FZTanHeiS-B-GB | FZCTHJW--GB1-0 |
| 方正特雅宋简体 | FZYaSongS-H-GB | FZTYSJW--GB1-0 |
| 方正粉丝天下简体 | FZFenSTXS-R-GB | FZFENSTXJW--GB1-0 |
| 站酷小薇 | xiaowei | xiaowei |
| 站酷高端黑 | huxiaobo-gdh | huxiaobo-gdh |
| 站酷快乐体2016修订版 | HappyZcool-2016 | HappyZcool-2016 |

只按产品名建清单，这些全会被判成「不在已购清单内」。**aliases 里必须同时收：产品名、内部 family 名、PostScript 名（含与不含 `--GB1-0` 后缀）、文件名主干。**

**坑二：字体文件被改过名。** 文件名与内部记录不一致，是盗版或来源不明的常见特征。用 `font_info.py --all-names` 看 copyright / trademark：如果内部记录写的是别家厂商，这款字就不受「文件名上那个名字」的授权覆盖。

> 实测案例：两个名为 `ZCOOL Addict Italic 01.ttf` / `02.ttf` 的文件，内部原始记录是 `©1991 Bigelow & Holmes. All Rights Reserved.`，商标 `Lucida is a registered trademark of Bigelow & Holmes Inc.` —— 实际是 **Lucida Calligraphy Italic**，被改了 Windows 名冒充站酷字体。这不属于站酷免费商用范围，是按「已购站酷字体」使用就会踩雷的典型。
>
> **2026-09-19 已处置**：从可用列表移除，登记进 `assets/licensed-fonts.json` 的 `_excluded`（见下节）。

### 排除清单 `_excluded`（禁用项，不是"没登记"）

`licensed-fonts.json` 里除 `fonts`（可用）外，还有一个 `_excluded` 数组，登记**明确禁用**的字体：

```json
"_excluded": [
  { "label": "…", "names": ["别名1","别名2"],
    "recorded_as": "标称名", "actual_font": "实际字体", "vendor": "版权方",
    "reason": "为什么禁用", "status": "处置状态", "files": ["…"], "registry_keys": ["…"] }
]
```

- `audit.py` 会**先查 `_excluded` 再查 `fonts`** —— 排除项永远不该被"命中已购"洗白。
- 命中的单独出一节 **「⛔ 已知排除字体（高风险 · 立即替换）」**，排在普通 🚫 之前，并附实际字体、版权方、禁用原因。
- 匹配比主清单更严（模糊阈值 `len >= 8`），避免把正规字体误判成禁用。
- **加新排除项的时机**：发现"改名冒用"、版权方与标称不符、或用户明确要求禁用的字体。
- 排除 ≠ 卸载。**移除的是清单里的可用资格，本机字体文件可能仍在**，设计软件字体列表里还能选到 —— 报告里要写明这点，别让人以为已经删干净了。

## 输出四档的含义

| 档位 | 含义 | 处置 |
|---|---|---|
| ✅ | 命中清单，且授权媒体覆盖本批物料、期限未过期 | 归档即可，报告里保留主体与备注提示 |
| ⚠️ | 命中清单，但用途/期限/主体存在疑点 | **拿授权书逐条核对**，不是"已合规" |
| ⛔ | 命中 `_excluded` 排除清单 | **立即替换**，并同步改设计源文件；有据可查的禁用项 |
| 🚫 | **当前清单里没有** | 列为风险项 + 给清单内的替代字体；**不向用户追问是否已购** |

**"买过" ≠ "什么场景都能用"。** 字体授权通常限定：
- **媒体**：印刷 / 网络 / 视频 / 商标 —— **本批素材固定为「线上线下全平台」，因此要求线上+线下同时覆盖**；
  只买印刷授权（或只买网络授权）的字体在做全平台投放时**不能直接用**，会降 ⚠️
- **主体**：集团 or 仅某子公司；**外包设计公司**做的图常常超出本单位授权
- **期限**：到期后继续使用即侵权
- **台数/并发**

逐条核对授权书的清单见 `references/授权书核对清单.md`（含 6 类核对项与 6 个常见误区）。

## 工作流

**范围：以下每一步都只针对用户在本次消息里点名的那一个文件**（见文首「审查范围」），
任何一步都不要扩大文件集合。

0. **（换电脑后必做）** 先跑 `scripts/check_fonts.py assets/licensed-fonts.json`，
   确认已购字体装齐了再开审。第 2 层缺字体时会拒跑而不是给错答案，但提前体检更省事；
   同一条命令还会提醒 `_excluded` 里的禁用字体是否仍装在本机。
1. 确定投放媒体：**默认即「线上线下全平台」，不再询问**（物料所属公司 2026-09-19 指定）。
   只有用户当次明确说"这批只投 XX"时才覆盖默认值
2. 有源文件 → 跑第 1 步；拿不到字体名的文件记下来
3. 对上一步没覆盖到的成图 → 跑第 2 步（先自己读图取出文字与框位）
4. 全部字体名汇总 → 跑第 3 步出四档报告
5. 报告里必须区分**结论**（元数据）与**线索**（字形打分），不要把线索写成结论
6. 结尾固定附一句：最终授权结论以字体权利方授权书为准；并注明本次比对所用的**清单版本/更新时间**
7. **查到 🚫 不追问用户**（见上「⚠️」）—— 直接给替代方案，交付不因此停顿
8. **与广告法审查联动** —— 审宣传物料时，广告法（`ad-compliance-check`）和字体版权是同一批图上的**两条独立风险线**，只查一条会漏另一条。**审完广告法要顺手跑字体比对**。两份工作还共用同一批"文字框位"信息，可以互相复用，不必重新定位。
   ⚠️ 这句"顺手跑字体比对"指的是**对同一个文件**再跑一条线，
   **不是**"把同目录的其它图也一起跑"——文件集合始终只有用户发来的那一个（见文首「审查范围」）。

### 脚本侧修掉的三个真 bug

1. **`otsu()` 在纯二值输入上返回 0** —— 只有 0 / 255 两个灰阶时，Otsu 最优点落在最小灰阶上，`v < thr` 取不到任何像素，程序报"裁切区域内找不到文字"并**跳过全部样张**。修法：阈值落在最小灰阶时取两阶中点。正是"先二值化"这一步把它暴露出来的。
2. **彩色字与黑色渲染的灰度偏差** —— 见上文「三条硬要求」第 1 条。
3. **`/RunLengthArray` 没做按位对齐（坑四名不副实）** —— 文档早就写了"要按 run 长度逐段归属"，
   但代码只是把作用域里所有 `/Font N` 收一遍，**长度数组根本没读**。
   后果是双向的：既可能把声明未用的字体报成 🚫（误报），也会把"只有一个数字用到的字体"漏掉。
   2026-09-20 补上并回归：与 `psd_tools` 逐层对拍 **50 层零差异**（7月23日 10 层 + 7.30 40 层），
   四档总结论不变（✅3/🚫1）。
   **教训**：文档写了"已内置"不等于真的内置 —— 换机器/换人复核时，要拿真值（`psd_tools`）对拍一次，
   而不是相信注释。

### 实战（可移植性：模拟"没装字体的电脑"）

起因是「把技能拷到别的电脑还能不能识别」这个问题。逐脚本核对依赖后做了定向测试：

- **第 1 层 + 第 3 段完全不依赖本机字体。** 实测换机器后对同一份 PSD
  （2026.7.30 全款福利政策）重跑，结论与改造前**逐字一致**：✅3 / 🚫1。
- **第 2 层改造成「按文件名在系统字体目录里找」后，覆盖率可见。**
  本机实测（当时那份清单共 30 款，下同）：本机找到 **29 款（96.7%）**，唯一缺的是
  **方正兰亭大黑 `FZLTDHJW.TTF`** —— 与清单里早就记着的备注吻合，不是新问题。
- **拒跑逻辑实测（三条分支都验过）**：
  - 干净机器（连系统字体都没有）→ `已购 0/30`，明确拒跑，退出码 **3**
  - 只装 3 款已购 + 系统字体（**最危险的情形**）→ `已购 3/30`，拒跑并列出缺的 27 款
  - 加 `--allow-partial` → 放行，但先打出「不可用于定款」的告警
- **这套改造修掉的是一个静默 bug，不是一个崩溃。** 改之前，缺字体时脚本
  **不报错**、照常输出排名 —— 实测把未购对照的微软雅黑推到第 1 名。
  更隐蔽的是：微软雅黑本来是我们特意放的**反例**，在干净机器上反例成了唯一候选，
  等于把「必须加未购对照」这条设计前提整个推翻。
- **报告侧同步加固**：`audit.py` 现在会把候选池覆盖率与缺席字体写进报告正文，
  避免出现「报告里抄了一串名次、却没人知道候选池缺了多少」的不可复核结论。

### 加固（2026-09-20：PSD 分支按位对齐 + 智能对象拆解）

起因是同事在另一台机器上跑 PSD 素材时发现 `extract_fonts.py` 的坑四**没有真正实现**。
本次把 PSD 分支整体加固，逐项都用真值验过：

| 项 | 做法 | 验证 |
|---|---|---|
| RunLengthArray 按位对齐 | `/RunArray` 与 `/RunLengthArray` 按下标配对，逐段累加字符数；0 长度不计入 | 与 `psd_tools` 逐层对拍 **50 层零差异** |
| 括号配对 | 自写平衡扫描（`/Values [ ... ]` 这类嵌套数组会让正则非贪婪停在错位置） | 同上（层级结构全部解析正确） |
| 字符串转义 | 逐字节扫描，`0x5C` 吞下一字节（汉字里就有 `0x5C`/`0x29`） | `/Text` 与 `psd_tools` 的 `Editor.Text` 逐字一致 |
| 名字解码 | BOM → UTF-16BE；纯 ASCII → ascii；含 NUL → 无 BOM 的 UTF-16BE；其余先 GBK | 两份 PSD 的 `/FontSet` 全部解出正确 PostScript 名 |
| 逐层映射 | 输出「图层文字 → 字体 → 字数」，进 JSON 的 `psd_layers` | `--psd-layers` 40 行逐层核过 |
| 智能对象拆解 | 拆出内嵌 PSB/AI/PDF/PNG 递归解析 | 实测 6 个对象：内部均无字体信息（已转曲/位图），把盲区变成可确认结论 |
| 声明未用 | FontSet 里 0 字符的字体写入备注（**按名字判重**，同款字重复登记不误报） | 7月23日那份正确报出 `AdobeHeitiStd-Regular`、`SimSun` |

**总结论不受影响**：两份 PSD 重跑后仍是 ✅2（7月23日）、✅3/🚫1（7.30），
与修复前一致 —— 修复的是"哪些字体、各多少字"的**归属精度**，不是四档档位。
