# 宣传物料合规审查 · 广告法违禁词 + 字体版权

一套面向**宣传物料（推图 / 海报 / 招生简章 / 设计需求单）**的合规审查技能包，含两条**互相独立**的风险线：

| 技能 | 管什么 | 交付物 |
|---|---|---|
| [`ad-compliance-check`](ad-compliance-check/) | 广告法违禁词、绝对化用语、保证性承诺、价格与赠品合规 | **标注图**（红/橙/黄框 + 编号）＋ **逐条结论表**（含 2–3 个替代词） |
| [`font-license-audit`](font-license-audit/) | 字体版权：图里用了什么字、在不在已购清单、授权范围够不够 | **四档报告**（✅ / ⚠️ / ⛔ / 🚫）＋ 字形比对记录 |

> **审一套物料时两条线都要跑。** 文案违禁和字体侵权是同一张图上的两个独立风险，
> 只查一条会漏另一条 —— 而且两条线共用同一批"文字框位"信息，框位可以复用，不必重新定位。

## 一、它能做到什么

### 广告法线

- **分级标注**：红（绝对化用语 / 保证性承诺 / 内部明令禁用词）、
  橙（赠品未明示 / 价格无基准 / 数据未标来源 / 限时可能失实）、黄（口径不一致 / 疑似错别字）
- **每处必给替代词**：2–3 个可直接抄进图里的写法，推图标题控制在 4–8 字；
  确实无法替换的写明「建议删除」或「需补 XXX」，不硬凑
- **四种输入形态**：
  1. **位图**（JPG / PNG）—— 坐标用像素墨迹投影 + 表格边框线检测，不靠目测
  2. **PSD 源文件**（最佳输入）—— 文案从图层里逐字读出，框位直接用 `layer.bbox`
  3. **文字稿 / 设计需求单**（Excel / Word / 纯文本，尚无成图）—— 不产标注图，出「问题清单 + 合规版文案」
  4. **内部合规文件**（用户提供的 PDF / Word / 需求单里的《违禁词参考》表）—— 优先级高于内置清单
- **忽略清单优先**：登记过的公司内部通用词直接跳过，不标框、不给替代词、也不为凑数列成"黄"

### 字体线

- **三层流程，按顺序用**：

  | 层 | 方法 | 可靠性 | 前提 |
  |---|---|---|---|
  | 1 | 源文件元数据提取（PSD / AI / PDF / PPTX / DOCX / XLSX） | **确定性**（100% 准确） | 有源文件 |
  | 2 | 字形比对打分（本机已购字体渲染后与成图逐像素比） | 量化排名 | 本机装了已购字体 |
  | 3 | 付费识别接口 | 候选 + 置信度 | 前两层都不行时的兜底 |

- **四档结论与处置**：

  | 档位 | 含义 | 你该做什么 |
  |---|---|---|
  | ✅ | 命中清单，授权媒体覆盖本批物料、期限未过期 | 归档即可 |
  | ⚠️ | 命中清单，但用途 / 期限 / 主体有疑点 | **拿授权书逐条核对**，不是"已合规" |
  | ⛔ | 命中排除清单（改名冒用、来源存疑） | **立即替换**，并同步改设计源文件 |
  | 🚫 | 当前清单里没有 | 列为风险项 + 给清单内的替代字体 |

- **候选池自检**：已购字体解析率低于门槛时**拒跑**（退出码 3），
  而不是静默给一份"矮子里拔将军"的排名 —— 这是本技能最重要的一道防线

## 四、安装

### 1. 放进技能目录

把两个技能目录**整个**复制过去（目录名必须保持原样，技能的识别靠这个名字）：

- Windows：`C:\Users\<你的用户名>\.workbuddy\skills\`
- macOS / Linux：`~/.workbuddy/skills/`

```
.workbuddy/skills/
├── ad-compliance-check/
│   └── SKILL.md
└── font-license-audit/
    └── SKILL.md
```

放着不管就行，不用注册。

### 2. 装 Python 依赖

```bash
pip install Pillow numpy psd-tools
```

| 包 | 用途 | 是否必须 |
|---|---|---|
| `Pillow` | 图片读取、标注、字形渲染 | **必须**，两个技能都要 |
| `numpy` | 框位计算（墨迹投影） | 必须（广告法那侧） |
| `psd-tools` | 解析 PSD 图层；拆解 PSD 里的**智能对象** | 可选，但审 PSD 时**建议装** |

> 少装 `Pillow` 会报 `ModuleNotFoundError: No module named 'PIL'`。
> 没装 `psd-tools` 不影响主线：逐层字体分析照常跑，只是智能对象内部的字体读不到，
> **脚本会在备注里写明**（不会静默跳过），装上后重跑即可。

### 3. 装字体（只影响字体线的第 2 层）

字体比对靠的是"拿已购字体渲染出字，跟图上的字比形状"，所以**本机得装着对应字体**。

装完先体检一次：

```bash
python font-license-audit/scripts/check_fonts.py font-license-audit/assets/licensed-fonts.json
```

它会告诉你清单里的字体装上了几款、还缺哪几款、该装到哪。

**字体装到哪个目录都行**，脚本会自动在系统字体目录里按文件名找；
装在非标准目录时用 `--font-dir` 或环境变量 `FONT_LICENSE_AUDIT_FONT_DIRS` 指定。

> 覆盖率低于 60% 时脚本会**拒绝出排名**，而不是勉强给一个。
> 看到拒跑提示说明本机字体不全 —— 这是故意的设计，避免拿到一份看着正常其实错的结论。

## 五、快速开始

### 用法一：直接把图丢给 AI

把图片或 PSD 直接丢进来就行。它会先问你这次要审哪一项：

> 广告法合规审核 / 版权字体审查 / 两者都要

选完才开跑，不会默认开审。也可以直接说「帮我审一下这张图，看有没有违禁词」，就跳过询问直接走广告法那条线。

> **发一张就审一张**，这是刻意的设计：不会去列你电脑上的目录，也不会把同一文件夹里别的图一起审掉。
> 确实想一次审多张时，在消息里明说（例如「这个文件夹里的图都看一遍」）——
> 它会**先把要审的文件清单列出来让你确认**，再动手，而且每张图分开出结论。

### 用法二：命令行（脱离 AI 也能跑）

**广告法线 · 位图标注**

```bash
# 1) 在原图窗口内做墨迹收紧，产出带编号的框位
python ad-compliance-check/scripts/build_boxes.py poster.png spec.json boxes.json

# 2) 在原图上画框
python ad-compliance-check/scripts/annotate.py poster.png boxes.json poster_标注.png
```

`boxes.json`（坐标均为 0–1 比例，`level` 1=红 2=橙 3=黄，第 6 位 `num` 为显式编号）：

```json
{
  "boxes": [
    [0.030, 0.185, 0.430, 0.275, 1, 1],
    [0.520, 0.230, 0.975, 0.275, 1, 1]
  ],
  "legend": true
}
```

> **一个编号 = 一条问题。** 同一条问题在图上 3 个位置都要标，就给这 3 个框写同一个 `num`，
> 这样图上编号与结论文档的条目数始终相等。
> ⚠️ 只要数组里出现过 `num`，**所有框都要写**，否则自动编号会和显式编号撞号。

**广告法线 · PSD 源文件**

```bash
python ad-compliance-check/scripts/psd_layers.py poster.psd --json layers.json
# 输出的 bbox 是像素坐标，除以画布尺寸即得 0–1 比例坐标
# 隐藏层会标 <<< 隐藏，不出图 —— 别给它们画框（会出"幽灵框"）
```

**字体线**

```bash
cd font-license-audit

# 0) 换电脑后的第一步：字体体检
python scripts/check_fonts.py assets/licensed-fonts.json

# 1) 第一层：从源文件提取字体名（有 PSD/AI/PDF/PPTX/DOCX/XLSX 就走这条）
python scripts/extract_fonts.py poster.psd --json extracted.json --psd-layers

# 2) 第二层：只有成图时用（两步）
python scripts/extract_samples.py spec.json --out-dir work/
python scripts/glyph_match.py work/spec_bw.json --manifest assets/licensed-fonts.json --out glyph.json

# 3) 第三段：清单比对，出四档报告
python scripts/audit.py --extracted extracted.json \
                        --licensed assets/licensed-fonts.json \
                        --glyph glyph.json \
                        --out 字体版权报告.md
```

## 六、配置与参数

### 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `FONT_LICENSE_AUDIT_FONT_DIRS` | 追加字体目录，多个目录用系统路径分隔符隔开（Windows `;`，类 Unix `:`） | 系统字体目录 + 用户字体目录 |

### 常用参数

| 脚本 | 参数 | 说明 |
|---|---|---|
| `extract_fonts.py` | `--psd-layers` | 打印**逐层用字映射**（图层文字 → 字体 → 字数），排查误报时先看它 |
| | `--no-smart-objects` | 关掉 PSD 智能对象拆解（内嵌素材很大、只想快跑时用） |
| `glyph_match.py` | `--manifest` | 指定《已购字体清单》，已购候选自动生成，不必手工维护路径 |
| | `--min-coverage` | 已购字体覆盖率门槛（默认 0.6），低于此值拒跑 |
| | `--allow-partial` | 候选不全时强制放行；**结果只能用于缩小范围，不可用于定款** |
| `check_fonts.py` | `--font-dir` | 追加字体目录（可重复） |
| | `--min-coverage` | 体检的覆盖率门槛（默认 0.6） |
| `audit.py` | `--media` | 投放媒体；**默认「线上线下全平台」**，只有本批只投某一侧时才需要覆盖 |

### 退出码

| 脚本 | 码 | 含义 |
|---|---|---|
| `check_fonts.py` | 0 / 1 / 2 | 覆盖率达标 / 不足 / 清单读不了 |
| `glyph_match.py` | 0 / 3 | 正常出结果 / **候选池自检未通过，拒跑** |
| `publish` 类脚本 | — | 本仓库不含打包脚本，本仓库即分发包 |

## 七、常见问题

**Q：只有一张成图，能确认用的是哪款字吗？**
不能。字形比对给的是**排除性结论**（能排除多数未购字体、能缩小范围），
不能反证"就是某一款字"。要**确证性**结论必须有源文件（PSD/AI/PDF/PPTX/DOCX/XLSX）。

**Q：报告里说"当前清单中未见此款"，是不是就侵权了？**
不等于。清单记录的是"买了哪些"，漏登记是常见情况（历史上站酷酷黑、方正兰亭大黑都漏登过）。
所以措辞是「**当前清单中未见此款**」并直接给替代方案，而不是"确定侵权"。
**《已购字体清单》即唯一口径**，新增已购字体由使用者主动告知，补录后重跑即可刷新结论。

**Q：字形比对第一名和第二名只差几分，怎么办？**
看**跨样张统计**，不要只看单样张第一名 —— 单张第一名的偶然性很大。
判读顺序：① 平均分前几名是谁 ② 有没有"单点高分、其余靠后"的字体（那是误匹配）
③ 未购对照有没有冲到过第一（这才是真信号）。
分差 ≥15 分才可作强线索，5–15 分只能缩小范围，<5 分不要下结论。

**Q：为什么主标题没有字体结论？**
做了描边 / 渐变 / 立体特效后栅格化的标题，在源文件里**已经不是文字层**了。
偏偏它常常是全图最大的那行字 —— 报告里会把它单列在「本次未能覆盖」，**不能默认它没问题**。

**Q：标注框画歪了怎么办？**
改 `boxes.json` 里的比例坐标重跑 `annotate.py`，**别一次跑完就交付**。
位图拿坐标不要目测估比例（叠网格读数误差仍有 0.02–0.05 ≈ 40–90px），
用像素墨迹投影扫一轮就能压准。**`boxes.json` 要与标注图一起留档**，
物料要改版时没有原始坐标就得重新定位一遍。

**Q：PSD 里明明有这个图层，为什么框画在了别的字上？**
图层存在 ≠ 图层出图。`visible == 0` 的隐藏层、被上层色块完全盖住的层，
在合成图里都不显示，但 `bbox` 照样有值。**画框前先裁图核对**。

**Q：删掉了一个框，编号乱了。**
删框必重排编号，并**同步修改结论文档里的条目编号**，保证"图上编号 ↔ 文档编号"始终一一对应。

## 八、许可 / 数据与商标

代码以 **MIT** 许可发布，但以下几点需注意：

- `font-license-audit/assets/licensed-fonts.json` **仓内为示例数据**（3 条占位条目 + 1 条排除示例），
  不含任何单位的真实采购信息。使用时请替换为本单位自己的清单；
  `_excluded` 里保留的 ZCOOL/Lucida 条目来自公开可查的字体文件内部记录，
  作为「改名冒用」的填写范例与风险示范。
- 本仓库**不附带任何字体文件**。商业字体的使用需自行取得合法授权；
  清单只记录"买了哪些、能用在哪"，**不构成授权凭证**。
- 「中公」「offcn」等名称与标识归其权利人所有。

本仓库提供的是**风险筛查工具**，输出为风险定位与替换建议，
不构成法律意见，也不能替代法务审核。**最终授权结论以字体权利方出具的授权书为准。**
