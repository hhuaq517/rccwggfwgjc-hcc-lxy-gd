# 广告法合规审查（教培物料）

对招生推图/海报/宣传物料做广告法合规体检：逐条核对违禁表述，并在原图上按风险等级标注，输出一张"标注图 + 分条结论"。

## 何时使用

- **用户只丢了一个文件（图 / PSD / PDF / PPT…）过来、没说要审什么** —— 这是最常见的入口，
  先按「第 0 步」问清是广告法 / 字体 / 两者都要，再执行
- 用户给一张课程推图/海报/宣传图，要求"按广告法检查有没有违禁的地方"
- 用户要求"标注出来""哪些词不能用""合规审查""这些词改成什么"
- 用户提供**文字稿 / 设计需求单**（Excel·Word·纯文本，**尚无成图**）要求审文案 —— 不产标注图，出
  「问题清单 + 合规版文案」，见「输入是文字稿 / 设计需求单时」
- 用户提供了内部合规文件（PDF/Word/**需求单里附的《违禁词参考》表**）要求作为依据（优先用它，否则用 `references/compliance-rules.md` 内置清单）

## 审查范围（硬约束，优先级高于下文一切流程）

**只审用户在当前消息里点名/发送的那一个文件。发一个就审一个，不要扩大。**

- ❌ **禁止为了"了解上下文"去列目录**（`ls` / `glob` / `dir` / 遍历父文件夹）
- ❌ **禁止把同目录、同文件夹、名称相近的其它图一并审查** —— 哪怕是同一场活动的其它尺寸、
  `xxx-v1.png` 与 `xxx-v2.png` 这种看着像一套的，也不许自动带上
- ❌ **禁止"反正都在这儿，一起标了更省事"** —— 用户没要的交付物就是噪声
- ✅ 交付物只对应这一个文件：一张标注图 + 一份结论，输出文件名与被审文件一一对应
- ✅ 需要素材时**只读用户给的那一个路径**，不推断、不扩展

**唯一例外**：用户在**当前消息**里明确说了范围，例如"这个文件夹里的图都看一遍""这几张一起审"。
此时也要**先把将要审的文件清单列出来给用户确认**，再执行；审完按文件分别出结论，不要混成一份。

**为什么写死这条**：用户丢一张图过来，要的是**这一张**有没有问题。
把同目录别的图一并审，会产出用户没要的交付物、结论与文件名对错号，
还会让用户以为"我只发了一张，怎么审了八张"。

## 第 0 步（强制）：先确认审查类型，再动手

用户**只把文件丢过来、没说要审什么**时，**不要默认开审** ——
先用 `AskUserQuestion` 问清 `审查类型`（三个选项）：**广告法合规审核 / 版权字体审查 / 两者都要**。

> ⚠️ 这里问的是**审查类型**（审哪条风险线），**不是文件范围**。
> 文件范围默认就是"用户发来的那一个"（见上节），不需要问、也不允许自行扩大。

- 用户选了含广告法线的选项 → 按本技能往下走。
- 用户只选「版权字体审查」→ 转 `font-license-audit`，广告法线不跑。
- **用户已明确说"看广告法""有没有违禁词"→ 跳过询问，直接执行。**
- **同一份文件、同一个会话只问一次**，除非用户主动改口。

## 工作流

1. **读图**：先 `Read` 图片，看清图上所有文案（主标题、副标题、福利区、价格表、脚注、倒计时等）。
   **只读用户发来的那一个文件**——不要列目录、不要把同目录其它图拉进来（见上上节「审查范围」）。
2. **定依据**：若用户给了内部合规文件，先用 pypdf 等提取文本作为判定依据；否则直接加载 `references/compliance-rules.md`（内置广告法 + 教培红线清单）。
3. **逐条比对**：**先过一遍 `references/ignored-terms.md`（忽略清单，优先级最高）**——登记过的公司内部通用词直接跳过，不标框、不给替代词、也不要为凑数把它列成"黄"。然后再按下面「必查 6 类」扫描文案，标记问题点，判定风险等级：
   - **红（高风险）**：绝对化用语、保证性承诺、内部明令禁用词（如"保驾护航""最长""无限"）
   - **橙（中风险）**：赠品未明示、价格无基准、数据未标来源、限时表述可能失实
   - **黄（提示）**：口径不一致、疑似错别字等
   - **每判一处，立刻给替代词**：从 `references/replacement-words.md` 挑 2–3 个可直接抄进图里的替代写法。**硬要求，不允许只指出问题、把改词这件事退回给用户。**
4. **画标注框**：用 `scripts/annotate.py` 在原图上画框，框坐标用**图片比例（0–1 的小数）**，与图片分辨率无关。
5. **输出结论**：给出标注图 + **表格形式的结论**（见「输出模板」，默认用 Markdown 表格，直接发在聊天框里），红橙黄分级。合规的点也要点一句，证明已核过。

## 输入是 PSD 源文件时（最佳输入）

拿到 PSD 就别靠肉眼读图 —— **文字内容可以从图层里直接读出来，一字不差**，也不会漏掉小字和脚注。

1. **渲染成图**：装 `psd-tools`（`python -m pip install psd-tools`），
   `PSDImage.open(p).composite()` 得到合成图，存 PNG 后既可用于 `Read` 看版式，也直接喂给 `annotate.py`。
2. **读文案**：遍历 `psd.descendants()`，取 `layer.kind == 'type'` 的层，`layer.text` 就是原始文案（`\r` 是换行）。
3. **框位不用目测**：`layer.bbox` 直接给出像素坐标，除以画布尺寸就是 0–1 比例坐标，
   **比肉眼估框准得多**，也不用反复调。橙色药丸/白底卡片这类装饰是 `kind == 'shape'` 或 `pixel` 层，其 bbox 用来框住整块。
   两个现成脚本（配套用，都在 `scripts/`）：
   - `python scripts/psd_layers.py <psd> --json layers.json` —— 列出全部图层的 kind / 可见性 / bbox / 文案，
     隐藏层会标 `<<< 隐藏，不出图`
   - `python scripts/build_boxes.py <合成图.png> <spec.json> <boxes.json>` —— 按上面给的窗口做**墨迹收紧**，
     多行图层可 `"line": [i, n]` 只取第 i 行，直接产出 `annotate.py` 能吃的 `boxes.json`
4. **主标题可能是栅格化的位图**：做了描边/渐变/立体特效的标题，设计师常常栅格化后合并，
   **PSD 里就没有文字层了**。这时用墨迹阈值反查位置（灰度 < 200 的行列投影取边界），
   并**在结论里注明"该处字体无法从源文件确认"**——最容易出事的往往是最大的那个标题，不能默认它没问题。
   ⚠️ 深色底（红/黑底）整块的灰度可能就小于 200，直接卡阈值会把背景全判成墨迹。
   改按**颜色**取掩码（例如白字 + 黄字：`R>200&G>200&B>200` 或 `R>190&G>140&B<140`），排除底色频道。
5. **⚠️ 图层存在 ≠ 图层出图（最容易画出"幽灵框"的一步）**。PSD 里常常留着
   **不可见图层**（`layer.visible == 0`）和**被上层色块完全盖住的图层**——两者在合成图里都不显示，
   但 `layer.bbox` 照样有值、`layer.text` 照样读得到。直接按 bbox 画框，就会在原图无关文字上
   画出一个"幽灵框"，编号与表格对不上，用户拿去核对会以为审错了地方。
   实测案例：「教师招聘产品」卡里有一层「福利三·奖金班免费升级为12天集训班」，
   被上一行色块的米色底盖住、整层不出图——按它画框正好压在「粤师2年就业全程营」那行字上。
   ✅ 做法：**画框前先裁图核对**。对每个待标注层裁出 `bbox` 区域 `Read` 一次，
   确认框里的文字确实是目标文案；`visible == 0` 的直接跳过。
   （自动化的两难：按"墨迹占比"判遮挡会被上层文字顶掉信号，按"图层自渲染 vs 合成图的 IoU"又受
   抗锯齿与渐变影响不稳 —— **裁图人眼核对最可靠**，几十个框也就是几次 Read。）
6. **一个图层里有两处不同问题时，按行拆框**。多行文字层的 bbox 是整块，
   若第一行属问题 A、第二行属问题 B，就把 bbox 的 y 区间按行切分，各自收紧到该行的墨迹，
   分别写进 `boxes.json`（两个框、两个编号）。用 `scripts/build_boxes.py` 的 `"line": [i, n]` 一步到位。
   ⚠️ 行数切出来与预期不符时（字距/描边导致间隙粘连），脚本会退化为等分，仍需**裁图复核**。
   实测：一个图层同时含「大咖旗舰班」（问题 8，第 1 行）与「7月31日后全面下架」（问题 5，第 2 行），
   拆成两个框后编号与表格才对得上。

⚠️ PSD 图层名很长（等于把内容当图层名），读图前先按"实际显示文案"核对一遍，别把图层名当图上内容。
⚠️ 读出来的文案块数（如 40 个）**不等于图上文案处数** —— 减去隐藏层、被遮挡层才是实际可见数。
结论里两处"看不见的事"值得单独交代：**隐藏的残留层**（原本要显示却漏删）与**被遮挡的残留层**（漏删还被盖住），
都能帮设计顺手清理 PSD。

## 输入是文字稿 / 设计需求单（Excel·Word·纯文本，**尚无成图**）时

这是**审得最早、改起来最便宜**的一种输入：文案还没做成图，动字就是动字，零返工成本。
常见载体是运营发来的《设计需求单》表格（"广告文案和内容写在这里"那一栏）。

- **不产出标注图**——没有图可标。交付物 = 「问题清单表格 ＋ **可直接替换的合规版文案**」。
  结论开头要写明"本件为文字需求单，尚无成图，故不出标注图"，并提示**设计出图后再按图审一遍**
  （图文不一致是这一版之后新增的风险）。
- **先分辨哪些单元格才是本次需求**。需求单常有多行（`例` / `需求1` / `需求2`…），
  只有**被填了内容的那一块**才是受审对象；带「例」字的那行是**表格自带示例**，不算本次需求
  （把它写进"备注"提一句即可）。其余子表多为空模板（尺寸/时间参考、课表位），读到空即止，不要当内容审。
- **"设计说明"那一栏同样要审**。运营写在"尺寸、色调、风格及其他要求"里的元素指令**也会落到图上**。
  实测：需求写"每个班次系列旁边都加一个小印章【**即将下架**】"——这就是一处会被印出来 5 次的紧迫感表述，
  必须与正文一起判；还要提醒运营/设计：**印章文案必须写死绝对日期**，否则设计师会自行填"倒计时 X 天"。
- **物料自带合规文件就用它当依据**。需求单常附《违禁词参考》子表——那是**公司口径，优先级最高**。
  引用时写明"内部清单第 X 行"，比只引通用规则更站得住，也便于用户回查。
- **班型名 / 产品名里含禁用词，是最容易漏的一类**。审文案时容易只扫"宣传语"，
  但**班型名会以最大字号印在海报上**。实测：「粤师畅学营」里的「**畅学**」被内部清单单独列为禁用词；
  「登科计划」的"登科"与清单里"上岸 / 入编 / 通关"属同一"考试成功"意义词族。
  处理口径：**照常报红/橙**，但替代词里给"若为集团正式班型名必须保留"这条出路（要求产品/法务出具备案依据），
  **不要替用户决定改名**。
- **年度标识与内部简称单独扫一遍**：「520在职」「27粤事」这类内部代号外部受众读不懂（同"散考/27统考"）；
  "2027公职类考试"要与**公告/大纲是否已发布**对齐口径。
- 需求单里通常**还没有价格、优惠、退费、赠品**——价格类风险天然为零，这一点要写进"合规亮点"；
  同时留意**排期与静态文案的冲突**（实测：需求时间 9/20、需完成时间 9/22、下架日 9/22 —— 图一出街当天即过期）。

## 必查 6 类（违禁清单见 `references/compliance-rules.md`，替代写法见 `references/replacement-words.md`，**忽略词见 `references/ignored-terms.md`，其优先级高于全部规则**）

1. **绝对化/极限词**：国家级、最 X、第一、顶级、唯一、100%、无限 等。
2. **保证性承诺**：包过/保过/保证/保障/保驾/护航/无忧/上岸/提分/预测/押题，以及"押/密/秘"相关任何谐音。
   还有一类容易漏的**适用范围承诺**——"均适配""全部适用""各类考试通用""全学段适用"。
   查这类时不能只看词，还要**核对课程科目与所宣称考试是否真的对得上**（例：课程含"公基"，但国考不考公基，写"国考均适配"就是夸大适用范围）。
3. **贩卖焦虑/制造紧张**：倒计时、随时结束、最后一波、全面下架、考纲变化、考试难度加大 等（限时促销须真实且注明具体时间）。
4. **价格与优惠**：原价/现价须有区别，原价 7 日内须有成交记录；赠品须明示品种/规格/数量/期限/领取方法；限量须注明数量；优惠须注明活动时间。
5. **数据宣称**：通过率、累计学员数、课时数等必须真实并标注来源、时间点、范围。
6. **贬低同行 / 借用权威**：不得贬低其他机构；不得用名师/名校/官方指定/命题组等。
   注意「明师」已登记忽略（见 `ignored-terms.md`），但「名师 / 大咖 / 一线名师」**仍照常报**——忽略清单只覆盖登记的那一个词，不外推。

## 标注脚本用法

```bash
python scripts/annotate.py <图片绝对路径> <boxes.json 绝对路径> <输出png绝对路径>
```

`boxes.json` 结构（坐标均为 0–1 比例，level 1=红 2=橙 3=黄）：

```json
{
  "boxes": [
    [0.030, 0.185, 0.430, 0.275, 1],
    [0.030, 0.185, 0.430, 0.275, 1, 1],
    [0.520, 0.230, 0.975, 0.275, 1, 1]
  ],
  "legend": true
}
```

**第 6 位 `num` = 显式编号，可选但很实用。** 规矩是「一个编号 = 一条问题」：
同一条问题在图上 3 个位置都要标，就给这 3 个框写同一个 `num`，
这样**图上编号与结论文档的条目数始终相等**，不会因为重复处把条目撑成一串同义项。
⚠️ 只要数组里出现过 `num`，**所有框都要写**，否则自动编号会和显式编号撞号。

脚本会：读取图片 → 按比例换算画 7px 红/橙/黄框 + 左上角白字编号圆点 → 底部追加图例条 → 保存。
**编号徽标尺寸自适应**：按「最矮的那个框」反推半径（`r = clamp(最矮框高 × 0.42, 11, 34)`）。
密集标注时（同一块的上下两行各一个框、行距仅 30px），固定 34px 半径的徽标会互相压住、
数字糊成一团——自适应后小框上的徽标会自动缩小。大图上框都很高时仍是 34px，与旧行为一致。
依赖 Pillow。编号与图例用的字体走**跨平台候选表**（Windows `arialbd.ttf` / `msyh.ttc` → macOS `Arial Bold.ttf` / `STHeiti Medium.ttc` → Linux `DejaVuSans-Bold.ttf` / `Noto Sans CJK`），逐个探测到能用的为止；全部找不到才回退默认位图字体，并在 stderr 打一行告警（默认字体不含中文字形，图例会变成空白或方框——这个降级不报错，只看产出图容易漏）。

画框后**务必再 `Read` 一次标注图**核对框是否压住目标文字；位置偏差就改 `boxes.json` 里的比例坐标重跑（不要一次跑完就交付）。

### 位图物料（JPG/PNG）怎么拿准坐标：用墨迹投影，别目测

没有 PSD 图层坐标时，**不要靠"看图估比例"**——叠一层 0.05 网格再读，误差仍常有 0.02–0.05（≈40–90px），
框会压到隔壁字上，来回改三四轮很常见。改用**一次性的像素扫描**，一轮就能压准：

```python
from PIL import Image; import numpy as np
im = Image.open(src).convert("RGB"); W, H = im.size
a = np.asarray(im).astype(int); gray = a.mean(axis=2)
dark = gray < 150          # 同时捞到黑字与红字；绿色/浅黄底（灰阶>180）被排除
```

按**行投影**切文字带、按**列投影**切文字块，全部换算成 0–1 比例：

- `rows = dark[y0:y1, x0:x1].sum(axis=1)`；连续 `>= minpx` 的区间就是一条文字行 → 给出该行 `y0/y1`
- 对该行再求列投影，取 `>0` 的列区间并按「字间空隙」合并 → 给出每段文字的 `x0/x1`（即"标签"与"正文"的边界）
- **表格**：先找**边框线**再定行列——横线 = 该行暗像素 > 0.8 × 区域宽度；竖线 = 该列暗像素 > 0.75 × 区域高度。
  拿到 `竖线 x = [0.523, 0.607, 0.728, 0.820, 0.942]` 就直接得到四个列区间，比数格子准得多。
- **白底上的人物/数字/彩色大字**（如橙色渐变的大数字）灰阶可能 >150，另用「非白掩码」`gray < 235`
  或按颜色取（橙 `R>200 & G 130–190 & B<120`）单独定位。
- **红底白字**的条幅：红底本身灰阶 <150，所以 `dark` 掩码的 bbox 就是**整条红底的范围**（白字不会扩大它）——正好是你要的框。

⚠️ 三个坑：
1. **红底/深色块会污染行投影**（"课程安排"红色横幅会被当成一行文字）——按 x 范围区分，或先排除已知色块区间。
2. **彩色标签（橙底白字）常被阈值漏掉**：文字块的 `x_min` 会落在正文而不是标签上，别把标签漏在框外；需要时按橙色单独取。
3. **合并间隙别设太大**：`gap` 取 10–14px 时能把"字间空隙"连成段，又不会把相邻两列粘在一起（列间距通常只有 5–10px，靠"竖线检测"而不是靠 `gap` 来切列）。

扫完仍要**裁图复核**（尤其倾斜的元素，如斜放的黄色药丸，矩形框四角会有富余）。

**`boxes.json` 要与标注图一起留档。** 物料图一旦要改（去掉某处、重排编号、补新发现），没有原始坐标就得重新定位一遍，代价很高。
若只剩标注图、坐标丢了，可按框线颜色反解（红 230,30,30 / 橙 245,130,20 / 黄 230,180,0，7px 粗线）：
按颜色做掩码 → 取长度 ≥250px 的水平游程、按 y 相邻聚类成"边带" → x 范围重叠的相邻两条边带配成一个框。
编号徽标直径 68px，在这个长度阈值下会被自动过滤掉，不会污染结果。

**删框必重排编号。** 因忽略清单或复检而删掉某个框时，其余编号要整体前移，并**同步修改结论文档里的条目编号**，保证"图上编号 ↔ 文档编号"始终一一对应；否则用户拿图对文档会错位。改完两处都要 `Read` 复核。

## 替代词要求（硬要求）

**每判定一处违规，必须当场给出 2–3 个可直接抄进图里的替代写法。只指出问题、不给替代词，视为未完成。**

- **数量**：2–3 个，多了等于没给
- **长度**：贴近原文，推图标题控制在 4–8 字
- **格式**：用引号包裹，多个候选用 ` / ` 分隔
- **不得引入新风险**：不能删掉"最好"，却写上"100% 覆盖"
- **不虚构**：替代词只能删减或限定原意，不能凭空加数据、加承诺、加背书
- **确实无法替换的**：明确写「建议删除」或「需补 XXX（如数据来源）」，**不要硬凑替代词**
- **兜底**：对照表见 `references/replacement-words.md`；表里没有的按同原则临场拟，并把新词补回表里

## 输出模板（表格 — 默认形式）

**默认在聊天框用 Markdown 表格反馈**，不要写成大段分条文字——用户要的是一眼能扫完的对照表。

固定五列，顺序不要改：

| 编号 | 等级 | 原文 | 问题 | 建议替代（2–3 个） |

- **编号**：与标注图上的白点编号严格一一对应（删框后记得重排，见上）。
  **一个编号 = 一条问题**，同一条问题在图上多处出现时（如"三档福利都不是同一套规则"），
  这些框共用同一个编号，并在「原文」列注明"（3 处）"，避免把条目撑成一串同义项
- **等级**：`🔴 高` / `🟠 中` / `🟡 提示`（对应标注框红/橙/黄）
- **原文**：图上原话，用「」包裹；同一条涉及多处的写明处数，如「新大纲」（3 处）
- **问题**：违的是哪条规则 + 一句实质说明，**先把方向讲对再下结论**
- **建议替代**：2–3 个，用 ` / ` 分隔并加引号；无法替换的写「建议删除」或「需补 XXX」

排序：红 → 橙 → 黄；同等级内按图上从上到下的位置排。

表格后另起两行补充（不塞进表格，避免单元格过长）：
- **合规亮点**：写对的地方（证明已核过，不是为了凑字）
- **忽略词**：本次跳过的登记词（如「明师」），说明未计入、未画框

单条问题文字较长（≥3 个要点）时，允许该条单独用列表展开，但仍要在表格里保留一行摘要。

### 表格示例

| 编号 | 等级 | 原文 | 问题 | 建议替代（2–3 个） |
|---|---|---|---|---|
| 1 | 🔴 高 | 「全年无限学」 | 绝对化用语，且与协议期不符 | "协议期内可不限次数学习" / "一年内可重复听课" |
| 2 | 🔴 高 | 「保驾护航！享受职位险」 | "保驾""护航"均属内部明令禁用词 | "全程陪伴" / "配套服务支持" / "全周期学习服务" |
| 3 | 🟠 中 | 「加量不加价」 | 无价格基准可比 | "课时增加，价格不变（XX 课时 → XX 课时）" / "课时升级，价格保持一致" |
| 4 | 🟡 提示 | 截止 9.20 与下架 9.22 并存 | 两个时间点口径不一致 | 统一为 "活动时间：9 月 X 日 – 9 月 20 日" |

> 旧的分条式模板（`**编号. 「原文」**—— 问题；建议改为 …`）仍可作为**结论文档**落盘时的写法，
> 但**聊天框默认必须是表格**。两者条目编号必须一致。

### 案例一：中公「粤师畅学营」教师招聘推图（**旧版，倒计时 5 天**，红 3 橙 5 黄 1，共 9 条）

> ⚠️ 这是该海报的**早期版本**。同款海报后来改过版（倒计时 3 天 / 9月22日下架），
> 改版后重审出 **13 条**（多出适用范围承诺、退费承诺、语义断裂、脚注缺失 4 条），见 **案例六**。
> **改版图必须重新逐条审，不能照抄旧结论**——但下面这套"带替代词"的产物样式仍是标准写法。

**红（3 处）**
1. 「全年无限学」—— 绝对化用语，且与协议期不符；建议改为 "协议期内可不限次数学习" / "长期有效（截至 X 年 X 月 X 日）"。

### 案例二：中公「公考国庆刷题进阶营」（广东公考推图，红 1 橙 5 黄 1）

**红（1 处）**

1. 「原价2990元」—— 无"促销前 7 日内成交记录"支撑的"原价"属**虚构原价**（《明码标价和禁止价格欺诈规定》第 19 条）。这是价格类审查里最硬的一处，查价第一步就是要成交凭证。
   建议改为 "现价 399 元" / "课程价 399 元"；确有成交记录则补 "原价 2990 元（成交期间：X 月 X 日 – X 月 X 日）"。

**橙（5 处）**

2. 「国考、省考、广东选调生 均适配」—— **适用范围承诺**，且课程含"公基"而国考不考公基，科目与宣称范围对不上。
   建议改为 "覆盖国考、省考、广东选调生考情" / "按国考、省考、广东选调生考情编排"。
3. 「现仅需399元」—— "仅需"与原价构成价格对比链，原价失据则"仅需"一并失据。
   建议改为 "现价 399 元" / "课程价格 399 元"。
4. 「住宿费一口价100元」—— "一口价"是价格承诺，但缺住宿标准、是否含餐、是否必选。
   建议改为 "住宿费 100 元/人（标准双人间）" / "住宿自愿选择，费用 100 元"。
5. 「1、赠国省资料包」—— 品种与数量列得很全，唯独缺**领取方式与期限**。
   建议补 "报名后于中公 APP 领取" / "X 月 X 日前报名方可领取"。
6. 「2、全勤之星加赠（价值98元）」—— 两处："全勤"未定义判定标准；"价值98元"属无依据的价值宣称。
   建议改为 "全勤（全程出席无缺课）加赠" / "（官方定价 98 元）" / 或删去价值标注。

**黄（1 处）**

7. 「4、报班专属权益：报27公考课程可叠加优惠」—— 金额区间与对应额度已写明（这点比"最高立减XXX"规范得多），**仅缺活动时间**。
   建议补 "活动时间：X 月 X 日 – X 月 X 日"。

**该案例的合规亮点**（审查时也要夸奖写对的地方）："有一定基础学员可学"明确了适用人群；"9月27日前报班"给了具体截止时间；全图无"包过/上岸/押题/名师"等硬违禁词，无倒计时话术。

### 案例三：中公「27省考专属定制班·节日限定款」（广东公考推图，红 1 橙 5 黄 2）

**红（1 处）**

1. 「新大纲」（第三/四/五阶段共 3 处）—— 2027 年广东省考大纲按常规时间线尚未发布（公告前一年 12 月至当年 1 月），以未发布的考纲命名课程属**服务内容与事实不符**，是全图最实质的一条。
   建议改为 "10天理论精讲" / "10天理论系统精讲" / "10天理论精讲（考纲发布后同步调整）"。

**橙（5 处）**

2. 「9月20日 全面下架」—— 用停售制造紧迫感，且未说明下架对象。建议改为 "本期活动时间：9月X日 – 9月20日" / "本班型 9月20日 截止报名"。
3. 「下架倒计时 2天」—— **静态写死天数**：9 月 19 日投放、9 月 20 日下架，实际只剩 1 天却写"2 天"。建议删掉倒计时模块，改 "报名截止：9月20日"。
4. 「价格12490起」—— **"起"是起步价、标示最低价，即暗示往上还有更高的价位**（不是暗示有更低价，方向别搞反）。本条风险不在"有无更低价"，而在两处：未写明 12490 对应哪个班型；无法确认存在高于 12490 的价位。建议改为 "12490 元起（基础班型）" / "12490 元起（走读班，高阶班 XXXX 元）" / "课程价格 12490 元"。
5. 「现报班凭学生证/2人团报可叠加500优惠」—— 触发条件写得清楚（优点），缺"元"单位与活动时间。建议补 "……可叠加 500 元优惠（活动时间：X月X日 – 9月20日）"。
6. 「进面可选一期面试经典班，价值8990元」—— "价值8990元"属无依据的价值宣称；"进面可选一期"的条件写明了，可保留。建议改为 "（官方定价 8990 元）" 或直接删去价值标注。

**黄（2 处）**

7. 「节日限定款」—— "限定"未说明限量份数或限时区间。建议改为 "节日特惠款" / "节庆在售款（限 9月20日前报名）"。
8. 「第二轮学习计划：20天」—— 口径不一致：明细为 10天 + 10天 + 检测 2天 = 22 天。**查课程天数时要把每一轮的"标称天数"与"明细相加"对一遍**，另外两轮（≥24天、8天8晚=12天）都能对上，只有这轮对不上。

> **本案例中的忽略词**：图上另有一处「明师教学」，按 `references/ignored-terms.md` 已登记为公司内部通用词，
> **未计入上述风险项、未画框、未给替代词**。这是忽略清单在实战里的标准用法——登记过的词直接跳过，不凑数。

**该案例的合规亮点**：无任何硬违禁词与绝对化用语；**无通过率/学员数等数据宣称**（教培最容易出事的区域，本图干净）；"全真一/二/三模+申论批改"属服务描述不承诺结果；"进面可选"把赠送条件写明；"凭学生证/2人团报"把优惠触发条件写明；背景为自然风景，**未使用国旗、国徽、天安门等政治符号**（做"国庆/节庆"主题时最常踩的一条，本图避开了）。

### 案例四：中公「全项目今日福利政策」（**PSD 源文件**输入，红 1 橙 4 黄 1，共 6 条 / 图上 11 框）

输入是 PSD（1024×1024），走 `/font-license-audit/scripts` 同款思路：`psd-tools` 渲染合成图 + 遍历文字层读文案 + 直接用 `layer.bbox` 当框位。

> **编号约定**：本案例一条问题对应图上多个框 —— 5 号在三个档位块各一个框、6 号在三个档位标题各一个框。
> 表格只出 6 行，看表的人不会读到三条几乎一样的"赠品信息不全"。

**红（1 处）**

1. 「全款免费试学」+「全款免费试学3天(面授/网课均可)」（2 处）—— **全图最实质的一条**。
   "全款"与"免费"并置本身矛盾：顾客读"免费试学"理解成不用花钱，实际流程是先缴全款、试学期内再退。
   属引人误解的商业宣传（《广告法》第 4 条、第 28 条），也是价格类投诉与退费纠纷的高发点。
   建议改为 "全款报名后可试学3天(面授/网课均可)" / "先报名试学3天，不满意可申请退费" / **直接删去"免费"二字**。

**橙（4 处）**

2. 「不满意15个工作日可退」—— 三处不严：**"不满意"没有界定标准**；**没写是否全额退**（是否扣课时费/资料费）；
   **"15个工作日"是退款到账时限**，容易被读成退费申请时限。退费承诺与报名协议不一致即构成虚假宣传。
   建议改为 "试学期内不满意可申请退费，具体以报名协议约定为准" / "3天内可申请退费（扣除规则详见协议）"。

3. 「全项目今日福利政策」（主标题）—— **"今日"是相对时间，静态写死必过期**。
   这张图隔天还在群发、朋友圈、公众号长尾里流转（实际投放中几乎必然发生），"今日"就成了失实表述。
   配合看：全图**找不到活动起止时间**。建议改为 "7月23日福利政策（限当日报名享）" / "本周福利政策（活动时间：7月X日–X月X日）"。
   **"相对时间静态写死"是与"倒计时天数写死"同一类的坑，要单独归一条。**

4. 「以上为7月23日福利政策，详情请咨询客服」—— 这行是全图的**免责兜底，恰恰最不能含糊**：
   ① 只给日期，没给活动起止时间与适用范围；② **"详情请咨询客服"不能替代广告中应当明示的内容** ——
   优惠条件、名额、赠品规格、退费规则都属于应明示事项，一句"咨询客服"等于把关键信息从广告里抽走，
   客服口径与广告不一致时**广告本身要担责**。建议改为 "以上政策自7月23日起执行，至X月X日24:00截止" /
   "活动时间：7月23日–X月X日，名额与赠品规格见各分校公示"。

5. 三档福利条目（3 处，同一问题，共用编号）—— 结构都是"1、赠送XX；2、大额优惠XX元"，**缺口都在同一位置**：
   - **赠品没有品牌型号规格**（"AI学习机""小学豆耳机"只有名字。须明示品种/规格/数量/期限/领取方式）
   - **缺领取方式与领取期限**（只说"赠送""仅X个名额"，没说何时、何地、凭什么领）
   - **"全省仅限6个名额"**："全省"是范围宣称，限量数字须与实际一致且可举证
   - **优惠缺活动时间与叠加规则**（没说能不能与试学、赠品同享）
   - **"名额"计量不当**（金额优惠却写"每人仅限1个名额"，应说"每人限享1次"）
   建议改为 "赠 AI 学习机 1 台（型号 XXX），限 6 台，报名后于XX校区领取" /
   "优惠 2000 元（活动时间：7月23日–X月X日，每人限享 1 次，不与赠品叠加）"。

**黄（1 处）**

> **本案例的方法要点（新增输入形态）**：
> ① **先分辨哪一块才是"本次需求"**——需求单有 `例`/`需求1`/`需求2` 多块，带「例」字的是表格自带示例，

> ② **"设计说明"栏与正文同等对待**；③ **班型名单独扫一遍禁用词**，这是最容易漏的一类；
> ④ 结论开头写明"尚无成图、故不出标注图 + 出图后建议再按图审一遍"。
> ⑤ 读取途径：Windows 上用 sheetagent 的 `resolve_local_excel` 时，`local_path` **必须是 `/` 开头的绝对路径**，
> C 盘文件要写成 `//?/C:/Users/...`（写 `C:/...` 会被判非法、写 `/c/...` 会被解析成 `D:\c\...`）。
